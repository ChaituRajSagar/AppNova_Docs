# 2026-07-28 18:11 — Zero-silent-drop conversion: reason-required planner + enforcing coverage gate

## Why

Root-caused the April `c9afaa02` conversion that shipped with blank dropdowns,
a skinny UI, and 120+ manual fixes. The session's `file_map.json` marked **336
source files `action=DELETE` with an EMPTY `skip_reason`** — every PCDEC lookup
controller/model, the entire legacy Angular `src/app/**` tree, and all
`sass/*.scss`. Two independent failures let it ship:

1. The planner was allowed to drop a file with no reason. Nothing rejected it.
2. The aggregated Run-gate already computed coverage/parity/line-fidelity/seed
   signals, but `GATE_BLOCK_COVERAGE` / `GATE_BLOCK_PARITY` /
   `GATE_BLOCK_INCOMPLETE` all defaulted to `false`, so those signals were
   advisory — a conversion that dropped a third of the source still launched.

The clean `converted` map (182 SKIPPED rows, each with a real reason; PCDEC
lookups kept as REWRITE) proves the machinery can do it right; the fix makes
the right behaviour mandatory.

## Changes

### Planner — stop the silent drop at the source
- `backend/agents/pipeline/planner_polish.py` — `validate_planner_quality` now
  fails the planner on any `mappings[]` row that produces no target
  (`kind=="SKIPPED"` or `action=="DELETE"`) with a missing/empty `skip_reason`.
  Emits one aggregated failure listing the affected sources → the existing
  supervisor repair-dispatch fires on it (no new plumbing). Zero false
  positives: the clean `converted` map adds 0 failures.
- `backend/agents/prompts.py` — migration-planner prompt gains a hard rule:
  every `SKIPPED` row needs an **evidence-based** reason (junk/backup, unrouted
  version, or a named out-of-scope module). "Different target framework",
  "it's a lookup", and "styling replaced/SCSS absorbed" are explicitly **banned**
  skip reasons — those files must be ported/merged. Cites the c9afaa02
  regression so the model knows the failure mode.

### Run-gate — make coverage/parity blocking by default
- `backend/core/config.py` + `.env.example` — `APPNOVA_GATE_BLOCK_COVERAGE`,
  `APPNOVA_GATE_BLOCK_PARITY`, `APPNOVA_GATE_BLOCK_INCOMPLETE` flipped
  `false → true`. Set a flag back to `false` only for a deliberately partial demo.
- `backend/agents/verification_gate.py` — added a `_COVERAGE_FAMILY`
  (`file_coverage` + `line_count_fidelity` + `seed_completeness`) that promotes
  a `fail` OR `warn` to a hard block when `GATE_BLOCK_COVERAGE` is on. Previously
  only `file_coverage` `fail` was promotable; `line_count_fidelity` (stubbed/
  shrunk targets) and `seed_completeness` (empty dropdowns) emit `warn` and were
  silently advisory — the exact "works nothing like the old app" signals.

### Backstop — calibrated regression eval
- `backend/evals/filemap_gate.py` (new) + `backend/evals/cli.py` — new
  `python -m backend.evals filemap-gate <file_map.json> [--strict] [--exit-on-fail]`.
  Reasonless drops always block; banned-reason *text* is advisory (heuristic,
  noisy) unless `--strict`. Calibrated on the two real maps:
  - `c9afaa02` (regressed) → **FAIL**, exit 1 (336 reasonless drops)
  - `converted` (clean)    → **PASS**, exit 0 (0 reasonless; 13 advisory
    "SCSS absorbed" warnings surfaced, blocking only under `--strict`)

### Docs
- `README.md` — new invariant row (evidence-based drop reason), the three
  `GATE_BLOCK_*` env vars documented as default-ON, and the `filemap-gate`
  eval subcommand.

## Verification
- `py_compile` clean on all 6 edited/new modules.
- `filemap-gate` calibration: c9afaa02 exit 1, converted exit 0, converted
  `--strict` exit 1 — as designed.
- Live `validate_planner_quality`: fires the 336-row reason-required failure on
  c9afaa02, adds 0 failures on the clean map.
