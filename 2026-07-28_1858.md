# 2026-07-28 18:58 — No-file-left-behind (Phase 1-3) + card wave-order + wide-table scroll

Implements the three feature areas from the pasted 28-07 changelog, adapted to
THIS repo's layout (the changelog's flat `backend/agents/*.py` paths map to
`backend/agents/{pipeline,auditors,orchestration}/*.py` here; smoke scripts go
in `scripts/smoke/` per the existing convention). Every new guard is additive
and defaults to warn/observe or is flag-gated OFF, each wrapped in try/except
(fail-open for the guard, fail-closed for its verdict), so a bug in this work
cannot brick a currently-passing conversion.

## Reconciliation with the 2026-07-28_1811 turn

That earlier turn promoted `seed_completeness` + `line_count_fidelity` to
BLOCKING via a `_COVERAGE_FAMILY` set. This changelog's Phase 3 wants them
WARN-ONLY ("born observing"). Reconciled to the changelog: `_COVERAGE_FAMILY`
removed; only `file_coverage` remains block-promotable (`_COVERAGE_BLOCKABLE`);
seed/line now surface via dedicated warn-only readers. The reason-required
planner check from that turn is KEPT and extended (meaningfulness, below).

## Phase 1 — deterministic, active by default

- **planner skip_reason now checks MEANINGFULNESS, not just presence.**
  `planner_polish._reason_is_meaningful` rejects empty, <8 chars, alpha-free
  (`---`, `1.2`), and boilerplate (`n/a`, `skip`, `todo`, `see above`).
  `validate_planner_quality` flags any `kind=SKIPPED`/`action=DELETE` row that
  fails it (→ existing repair dispatch), exempting deterministic `_backfilled`
  rows. Closes the April c9afaa02 root cause (336 reasonless DELETEs).
- **Empty/stub targets no longer count as ported.**
  `file_coverage._target_is_nonempty` (0-byte, or ≤64-byte whitespace-only =
  empty) replaces the bare `is_file()` in `_resolve_row`.
- **Backfilled (planner-dropped) files count against coverage.** `_resolve_row`
  no longer short-circuits `_backfilled` rows to `skipped_by_map` (excluded
  from the denominator); they fall through and, if unproduced, count `unmapped`.

## Phase 2 — per-entry ledger (enforcement flag-gated OFF)

- **`backend/agents/pipeline/conversion_ledger.py` (new).** Builds
  `context/conversion_ledger.json` with `pending → done → verified` per convert
  row (`verified` = all targets non-empty AND a target cites the source in a
  `// Source:` header). Fail-closed; reuses `_target_is_nonempty`; carries an
  `attempts` counter forward across waves.
- **Wired passively into `supervisor.py`** after the coverage floor: always
  builds + reconciles + persists + logs pending. `APPNOVA_LEDGER_ENFORCE`
  (default off) additionally downgrades code-generation to status=error when
  entries remain pending — zero-tolerance, mirroring the coverage floor.
- **Cleanup turns can re-verify (`APPNOVA_CLEANUP_REVERIFY`, default off).**
  `main._schedule_recovery_chat_turn` gained an optional `reverify` hook that
  re-runs the auditor after the turn and logs whether the gap closed. Wired for
  both loops: coverage-cleanup re-runs `audit_file_coverage`, parity-cleanup
  re-runs `check_parity` (via `_reverify_parity_red`). Off = unchanged.

## Phase 3 — gate observability (boot probe flag-gated OFF)

- **Seed-completeness + line-fidelity feed the gate as WARN-ONLY inputs.** Both
  auditors persist a compact JSON (`docs/seed_completeness.json`,
  `docs/line_fidelity.json`, mirroring `field_parity.json`); `verification_gate`
  gained `_read_seed` / `_read_line_fidelity` and appends advisories (ids
  `seed`, `line-fidelity`) that never touch the blocking verdict.
- **`backend/agents/boot_probe.py` (new)** — the "Run-Converted starts clean"
  signal. stdlib-only, never raises; classifies route status, waits for HTTP,
  probes routes, tears the process down, writes `docs/boot_probe.json`. Gated
  by `APPNOVA_GATE_BOOT_PROBE` (default off). `verification_gate._read_boot_probe`
  adds a warn check (id `boot`). Module + reader unit-tested; NOT auto-invoked
  in the live pipeline yet (wiring the real app-launch argv is the flag-gated
  opt-in follow-up).

## Feature — report cards / sidebar in wave-topological order

- **`frontend/app.js` `AGENTS` reordered** to `code-analysis, architecture,
  business-rules, security, integration, data-migration, devops,
  migration-planner, code-generation, documentation, code-review, testing,
  ui-ux` — a valid topological order of `AgentSpec.upstream` (ui-ux wave 4 but
  listed last as the final preview step). One array drives both the sidebar and
  the 1..13 card numbers, so they can't disagree.
- **`README.md` agent table** Wave column corrected against the code:
  `documentation` 3→4 (consumes code-generation), `testing` 4→5 (consumes
  code-review). Column is now each agent's true `compute_waves()` wave, so it is
  deliberately non-monotonic (…4, 4, 5, 4); the note under the table says so.

## Feature — wide report-card tables scroll instead of clipping

- **`frontend/app.js` `renderMarkdown`** wraps every table in
  `<div class="report-table-wrap">`; `div` added to the block-tag allow-list
  (escapeHtml runs first, so the wrapper is the only `<div>` it emits).
- **`frontend/style.css`** `.report-table-wrap { overflow-x:auto; max-width:100%;
  min-width:0 }` (min-width:0 stops a wide table stretching the flex column);
  body cells `max-width:46ch; overflow-wrap:anywhere`, headers `nowrap`;
  `.final-report table` no longer `table-layout:fixed`. Covers both the final
  report and the live-streaming `.assistant-live` view.
- **Cache-bust:** index.html (`style.css?v=14`, `app.js?v=27`); hub.html
  (`v=13`), review.html (`v=13`), login.html (`v=10`).
